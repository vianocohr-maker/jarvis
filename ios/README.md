# The iOS client

A phone-shaped implementation of the same three interfaces the browser
implements — `AudioSource`, `FrameSource`, `AudioSink` — talking the wire
protocol in [`src/bridge/protocol.ts`](../src/bridge/protocol.ts). The backend
cannot tell it apart from the browser stand-in, which is what item 06 was for.

## No Mac required

Nobody on this project owns one. `.github/workflows/ios.yml` builds it on
GitHub's macOS runners, which are **free and unlimited on public repositories**,
and uploads an unsigned IPA. On a *private* repo macOS minutes bill at 10×, so
the 2,000-minute free tier becomes about 200 macOS minutes a month — check that
before flipping the repo private.

The project file is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml`. A `.pbxproj` is a large generated artefact that is miserable
to write by hand and merges badly; a 40-line YAML file is neither.

## Getting it onto a phone

1. Push, or run the workflow by hand from the Actions tab
2. Download the `Jarvis-unsigned-ipa` artifact and unzip it
3. Install [Sideloadly](https://sideloadly.io) on Windows
4. Plug the iPhone in, drag the IPA on, enter your **free** Apple ID
5. On the phone: Settings → General → VPN & Device Management → Trust

A free Apple ID signs for **7 days**, then the app stops opening and you re-run
Sideloadly. The $99/yr Apple Developer Program raises that to a year — worth it
only once you are using this daily.

## No keys, and nothing paid

Speech in is `SFSpeechRecognizer`, speech out is `AVSpeechSynthesizer`. Both are
built into iOS and free, and they line up with the server's existing
`STT_PROVIDER=browser` and `TTS_PROVIDER=client` paths — the phone sends text up
and speaks text back down, so no audio crosses the wire on a normal turn.
Recognition is pinned on-device wherever the language supports it, so what you
say does not leave the phone.

There are **no Swift Package dependencies at all**. That is deliberate: the first
build had to be as boring as possible, because debugging a dependency graph on a
machine you cannot log into is miserable.

## Using it with the glasses

Pair the Ray-Bans to the iPhone as you normally would and they become the
microphone and speakers — the audio session asks for `.allowBluetooth`
explicitly, without which iOS quietly records from the phone while playing
through the headset.

The glasses' **camera** is not here. It needs Meta's Device Access Toolkit,
which is a separate SDK and a separate registration; the client answers
`captureFrame` with an honest `frameError` so the server says it cannot see
rather than inventing an answer.

## Connecting

The bridge address defaults to `192.168.1.10:8787`. Change it with the gear
icon — the address is printed when the server boots. Phone and computer must be
on the same network.

## What is not here yet

- Wake word. Push-to-talk only; Porcupine needs an access key and a binary
  dependency, and the first build wanted neither.
- The glasses camera, as above.
- Background operation is declared in the plist but untested.
